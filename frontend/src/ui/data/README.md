# Shared demo sports records

- `matches.jsx` creates the only confirmed fixture/result dataset, initialized once per page session in the existing community provider. Challenges never append fixtures.
- `community.jsx` contains player/team identities and current membership only. Historical lineups are snapshots and may include past registered guests or clearly named, unregistered guest batters.
- Profiles, head-to-head results, player leaderboards, and team rankings use selectors over these same fixtures. Only completed, explicitly confirmed demo matches count in statistics. No-play results contribute team no-result points, not player performances.
- Current-month views filter fixture dates by the current month in Asia/Karachi. All-time views include the full recorded demo sample. No records are cleared or periodically reset.
- Historical football goalkeeper roles are stored on each fixture. Profile-position edits cannot create or erase past clean-sheet credit.
- The shared community store now starts with no active account. Session players, profile edits, memberships, per-player booking drafts, and demo requests share that store. Booking-created own teams use the existing team reducer; opponent IDs must reference a different registered team in the same sport. Requests never alter slot availability or create fixtures. Passwords are never stored. See `../STAGE1_REFINEMENT.md` for the connected account and booking workflows.
- Football demo format: two 20-minute halves. Goals and assists are derived from events. Goalkeeper clean sheets require a recorded appearance on a side conceding zero. The public clock reads a mock timestamp and caps at the current demo period; it never changes scores or status. All clock subscribers share one interval, removed when unused.
- Cricket demo format: ten overs, six wickets. Six legal deliveries form an over; wides add an extra run and bowler run without advancing legal balls or batter balls. Delivery scripts derive every batter/bowler total and the team score. Winning chases end on the winning delivery; all-out innings end on the sixth wicket. Unregistered guests are excluded from leaderboards.
- Batting strike rate = runs × 100 / balls faced (minimum 20 balls for ranking). Bowling economy = runs conceded × 6 / legal balls (minimum 12 legal balls for ranking). Economy sorts ascending. Rate rankings use unrounded values; displayed rates have two decimals. Players need recorded appearances and the relevant batting/bowling statistics.
- Football points: W=3, D=1, L=0; ties in table points use goal difference, goals for, then name. Cricket points: W=2, Tied=1, NR=1, L=0; ties in points use wins, then name. Player metric ties share ranks; names provide stable display order.
- No real events, reservations, verified performance, live networking, staff controls, automated resets, or backend persistence are implemented.
- Live and interrupted examples are independent fictional match-state snapshots for UI demonstration, not concurrent matches or a venue availability schedule. Completed fixtures are generated only when their mock completion time is in the past; early-month rankings can legitimately be empty.
